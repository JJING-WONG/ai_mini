# 통합 테스트 결과

## 자동 검증 완료

`npm run check`로 아래 검증을 실행합니다.

| 항목 | 결과 |
| --- | --- |
| ESLint | 통과 |
| Vitest | 6개 파일, 총 101개 통과 |
| 프로덕션 빌드 | 통과 |
| 빌드 HTML·제목·언어·JS·CSS 파일 검사 | 통과 |

로컬 HTTP 확인은 SPA 진입 HTML과 정적 파일 제공을 확인한 것입니다. Vercel의 실제 배포·rewrite 동작이나 화면 조작 검증을 대신하지 않습니다.

## 통합 테스트 범위

가상 DOM(jsdom)에서 실제 React 컴포넌트·라우터·Provider·Service·Repository를 함께 실행했습니다.

- StrictMode에서 첫 접속, 온보딩 초안 저장 및 재마운트 복원, 완료 후 홈 이동
- 공간·항목 선택 최소 조건, 직접 공간·항목 추가
- 항목 수정 시 기본 콘텐츠 연결 유지 및 명시적 해제, 기존 기록 유지
- 기록 작성·날짜 수정·삭제, 항목 삭제 시 연결 기록 삭제
- 삭제 취소 시 원본 유지, 저장 오류 시 입력 유지·재시도
- 연속 중복 제출 시 한 건 저장
- 미완료 사용자의 접근 분기, 완료 사용자의 시작 URL 이동, 404 및 없는 ID
- 저장 데이터 손상 시 원본 보존과 다시 불러오기
- 자정 타이머와 포커스 복귀에 따른 날짜·상태 갱신
- 미래 날짜 입력 오류 표시와 저장 차단

기존 Service·Repository 테스트는 윤년·월말·연말, 상태 경계, 네 시간대, 우선순위 정렬, 동일 날짜 기록, 메타데이터 유지, 저장 중단 복구 및 저장 후 재조회를 포함합니다.

테스트의 저장소는 격리된 메모리/가상 DOM 저장소입니다. 실제 사용자의 저장 데이터는 조작하지 않습니다. 재마운트 검증은 새 Provider의 재조회를 검증하며 실제 브라우저 새로고침 검증과 구분합니다.

## 실제 브라우저에서 남은 확인

브라우저 연결 도구가 `The browser access host is unavailable`을 반환해 다음 항목은 실행하지 못했습니다. `npm run dev` 또는 `npm run build` 후 `npm run preview`로 직접 확인할 수 있습니다.

- [ ] 온보딩 진행 중 새로고침, 탭 닫기·다시 열기 후 단계와 입력 복원
- [ ] 완료 후 `/` 접속 시 홈 이동, 상세 URL 직접 접속·새로고침
- [ ] 공간·항목·기록 추가·수정·삭제 후 새로고침해 데이터 유지
- [ ] 이미지 선택·교체·제거, 잘못된 파일·1MB 초과 파일 안내, 저장 후 재표시
- [ ] 삭제 확인창의 실제 포커스 가두기, Escape·취소·확정 및 이전 버튼으로 포커스 복귀
- [ ] 모바일 폭 320/375/390px에서 잘림·가로 스크롤·날짜 입력·고정 하단 버튼 확인
- [ ] 모바일 키보드가 열린 상태의 폼 스크롤과 저장 버튼 접근
- [ ] 새 날짜에 다시 열었을 때 상태 갱신, 실제 자정·백그라운드 복귀
- [ ] 브라우저 콘솔 오류 및 정적 파일 요청 실패 여부

jsdom에서는 native dialog의 열림/닫힘 상태만 대체했습니다. 실제 modal·레이아웃·이미지 디코딩·native 달력 동작은 자동 테스트 통과로 확인됐다고 판단하지 않습니다.

## 남은 사항

- 사용자가 Vercel 배포 후 배포 URL에서 직접 경로 접속·새로고침을 확인해야 합니다.
- 동일 데이터의 여러 탭 동시 편집 병합·동기화는 구현하지 않았습니다.
- 이전 온라인 npm audit에서 기존 ESLint/minimatch 개발 의존성의 moderate 4건을 확인했습니다. 강제 메이저 버전 변경은 적용하지 않았습니다.
- GitHub Actions 워크플로는 제거했으며, 원격 CI는 사용하지 않습니다. 로컬에서 `npm run check`로 검증합니다.
