# FUNCTIONAL_SPEC.md

## 1. 문서 개요

### 1.1 목적

본 문서는 자취생을 위한 주거 관리 웹서비스 '자취방 설명서'의 기능 요구사항을 정의한다.

각 기능의 입력값, 처리 규칙, 예외 상황 및 완료 기준을 명시하여 AI Vibe Coding을 활용한 구현과 검증의 기준으로 사용한다.

### 1.2 핵심 기능

| ID  | 기능           | 설명                                 |
| --- | -------------- | ------------------------------------ |
| F01 | 관리 대상 등록 | 공간별 관리 대상 등록 및 정보 관리   |
| F02 | 관리 주기 관리 | 관리 주기와 예정일 계산 및 상태 표시 |
| F03 | 관리 히스토리  | 관리 기록 등록, 조회, 수정 및 삭제   |

### 1.3 공통 설계 원칙

- 모바일 환경을 우선으로 설계한다.
- 기본 관리 항목과 사용자 직접 등록 항목을 모두 지원한다.
- 사용자가 모르는 정보는 임의로 생성하지 않는다.
- 관리 주기와 최근 관리일이 모두 존재해야 다음 관리 예정일을 계산한다.
- 최근 관리일은 히스토리에서 가장 최근의 실제 관리 날짜를 기준으로 계산한다.
- 관리 기록 변경 시 관련 일정과 관리 상태를 다시 계산한다.

## 2. F01. 관리 대상 등록

### F01-01. 공간 선택

**설명**

사용자는 자신의 집에 존재하는 공간을 선택하여 관리 대상을 공간별로 분류한다.

**입력값**

- 공간 ID
- 공간 이름

**처리 규칙**

1. 기본 공간 목록을 제공한다.
2. 사용자는 여러 공간을 선택할 수 있다.
3. 최소 1개 이상의 공간을 선택해야 한다.
4. 선택한 공간은 관리 대상 등록 과정에 반영한다.

**예외 처리**

- 공간을 선택하지 않은 경우 다음 단계로 이동할 수 없다.
- 선택한 공간이 없는 경우 선택 안내를 표시한다.

**완료 기준**

- [ ] 공간을 복수 선택할 수 있다.
- [ ] 선택한 공간이 유지된다.
- [ ] 공간 미선택 시 다음 단계 진행을 제한한다.

### F01-02. 기본 관리 항목 등록

**설명**

사용자는 공간별로 제공되는 기본 관리 항목을 선택하여 등록할 수 있다.

**처리 규칙**

1. 선택한 공간에 해당하는 기본 관리 항목을 표시한다.
2. 사용자는 필요한 항목을 선택한다.
3. 선택한 항목의 이름과 공간 정보를 등록한다.
4. 기본 항목에 권장 관리 주기가 존재하면 해당 주기를 자동 적용한다.
5. 권장 주기는 사용자가 수정할 수 있다.
6. 동일한 종류의 관리 대상을 여러 개 등록할 수 있다.

**완료 기준**

- [ ] 공간별 기본 관리 항목을 표시한다.
- [ ] 여러 관리 항목을 선택할 수 있다.
- [ ] 선택한 관리 항목을 등록할 수 있다.
- [ ] 권장 주기가 자동 적용된다.
- [ ] 권장 주기를 수정할 수 있다.

### F01-03. 관리 대상 직접 등록

**설명**

기본 목록에 없는 관리 대상을 사용자가 직접 등록할 수 있다.

**입력값**

| 항목           | 필수 여부 | 비고                |
| -------------- | --------- | ------------------- |
| 관리 대상 이름 | 필수      | 빈 문자열 불가      |
| 소속 공간      | 필수      | 선택한 공간         |
| 관리 주기      | 선택      | 양의 정수, 일 단위  |
| 최근 관리일    | 선택      | 오늘 또는 과거 날짜 |
| 모델명 및 규격 | 선택      | 텍스트              |
| 사진           | 선택      | 이미지              |
| 메모           | 선택      | 텍스트              |

**처리 규칙**

1. 이름과 공간이 입력되면 관리 대상을 등록할 수 있다.
2. 관리 주기를 모르면 입력하지 않아도 된다.
3. 관리 주기를 입력하지 않으면 '주기 미설정' 상태로 저장한다.
4. 최근 관리일을 입력하면 '초기 설정' 유형의 관리 기록을 생성한다.
5. 동일한 이름의 관리 대상 등록을 허용한다.

**예외 처리**

- 이름이 비어 있으면 등록을 제한한다.
- 공간이 지정되지 않으면 등록을 제한한다.
- 관리 주기가 0 이하이면 오류를 표시한다.
- 최근 관리일이 미래 날짜이면 등록을 제한한다.

**완료 기준**

- [ ] 이름과 공간만으로 등록할 수 있다.
- [ ] 관리 주기 없이 등록할 수 있다.
- [ ] 동일한 이름의 항목을 여러 개 등록할 수 있다.
- [ ] 입력한 최근 관리일이 초기 기록으로 저장된다.

### F01-04. 관리 대상 수정

**설명**

사용자는 등록된 관리 대상의 정보를 수정할 수 있다.

**수정 가능 정보**

- 이름
- 소속 공간
- 관리 주기
- 모델명 및 규격
- 사진
- 메모

**처리 규칙**

1. 수정한 정보는 저장 후 상세 화면과 목록에 반영한다.
2. 관리 주기를 수정하면 다음 관리 예정일을 재계산한다.
3. 최근 관리일은 별도 필드로 직접 수정하지 않는다.
4. 최근 관리일 변경은 관련 히스토리 기록을 수정하는 방식으로 처리한다.
5. 과거 히스토리는 관리 대상 정보 수정만으로 삭제되지 않는다.

**완료 기준**

- [ ] 관리 대상 정보를 수정할 수 있다.
- [ ] 변경 내용이 목록과 상세 화면에 반영된다.
- [ ] 주기 변경 시 예정일이 갱신된다.

### F01-05. 관리 대상 삭제

**설명**

사용자는 등록한 관리 대상을 삭제할 수 있다.

**처리 규칙**

1. 삭제 버튼 선택 시 확인창을 표시한다.
2. 관련 히스토리도 함께 삭제된다는 내용을 안내한다.
3. 사용자가 확인하면 관리 대상과 연결된 모든 관리 기록을 삭제한다.
4. 삭제 결과를 목록과 홈 대시보드에 반영한다.
5. 사용자가 취소하면 아무 데이터도 변경하지 않는다.

**완료 기준**

- [ ] 삭제 확인창을 표시한다.
- [ ] 취소 시 데이터가 유지된다.
- [ ] 확인 시 관리 대상과 관련 히스토리가 삭제된다.

## 3. F02. 관리 주기 관리

### F02-01. 관리 주기 설정

**설명**

사용자는 관리 대상별 관리 주기를 설정하거나 수정할 수 있다.

**처리 규칙**

1. 관리 주기는 일 단위로 관리한다.
2. 기본 항목은 권장 주기를 자동 적용한다.
3. 직접 등록 항목은 관리 주기를 선택적으로 입력한다.
4. 사용자는 적용된 관리 주기를 수정하거나 미설정 상태로 변경할 수 있다.
5. 관리 주기를 변경해도 과거 히스토리는 유지한다.
6. 관리 주기가 변경되면 다음 관리 예정일과 관리 상태를 재계산한다.

**완료 기준**

- [ ] 관리 주기를 설정할 수 있다.
- [ ] 관리 주기를 수정할 수 있다.
- [ ] 관리 주기 미설정을 지원한다.
- [ ] 주기 변경 시 예정일이 재계산된다.

### F02-02. 최근 관리일 계산

**설명**

최근 관리일은 해당 관리 대상에 연결된 히스토리의 실제 관리 날짜 중 가장 최근 날짜로 계산한다.

**계산 규칙**

`최근 관리일 = MAX(해당 항목의 관리 기록 날짜)`

**처리 규칙**

1. 초기 설정 기록과 관리 완료 기록을 모두 계산 대상으로 사용한다.
2. 기록을 생성한 시점이 아닌 실제 관리 날짜를 기준으로 한다.
3. 같은 날짜의 기록이 여러 개 존재해도 정상적으로 계산한다.
4. 모든 기록이 삭제되면 최근 관리일은 미설정 상태가 된다.

**완료 기준**

- [ ] 가장 최근의 실제 관리 날짜를 반환한다.
- [ ] 과거 기록을 나중에 추가해도 최근 관리일이 잘못 변경되지 않는다.
- [ ] 기록 수정·삭제 후 최근 관리일이 갱신된다.

### F02-03. 다음 관리 예정일 계산

**설명**

관리 주기와 최근 관리일을 기준으로 다음 관리 예정일을 계산한다.

**계산 규칙**

`다음 관리 예정일 = 최근 관리일 + 관리 주기(일)`

| 관리 주기 | 최근 관리일 | 결과        |
| --------- | ----------- | ----------- |
| 설정      | 설정        | 예정일 계산 |
| 설정      | 미설정      | 미설정      |
| 미설정    | 설정        | 미설정      |
| 미설정    | 미설정      | 미설정      |

**처리 규칙**

1. 두 값이 모두 존재하면 예정일을 계산한다.
2. 하나라도 없으면 예정일을 계산하지 않는다.
3. 관리 주기 변경 시 즉시 재계산한다.
4. 관리 기록 등록·수정·삭제 시 재계산한다.
5. 날짜 계산은 일 단위로 처리한다.

**완료 기준**

- [ ] 예정일을 정확하게 계산한다.
- [ ] 필수 계산 정보가 없으면 미설정으로 표시한다.
- [ ] 주기 또는 기록 변경 시 예정일이 갱신된다.

### F02-04. 관리 상태 분류

**설명**

관리 예정일과 오늘 날짜를 비교하여 관리 상태를 5단계로 분류한다.

| 상태      | 조건                   |
| --------- | ---------------------- |
| 관리 지연 | 예정일이 오늘보다 이전 |
| 오늘 관리 | 예정일이 오늘          |
| 관리 임박 | 예정일까지 1~7일       |
| 관리 예정 | 예정일까지 8일 이상    |
| 미설정    | 예정일 계산 불가       |

**처리 규칙**

1. 날짜 차이를 일 단위로 계산한다.
2. 예정일이 지났으면 관리 지연으로 표시한다.
3. 예정일이 오늘이면 오늘 관리로 표시한다.
4. 예정일까지 1~7일 남았으면 관리 임박으로 표시한다.
5. 예정일까지 8일 이상 남았으면 관리 예정으로 표시한다.
6. 계산에 필요한 값이 없으면 미설정으로 표시한다.

**완료 기준**

- [ ] 5개 상태를 정확하게 구분한다.
- [ ] 날짜가 바뀌면 상태가 올바르게 반영된다.
- [ ] 관리 기록 변경 시 상태가 갱신된다.

### F02-05. 홈 대시보드 표시

**설명**

홈 대시보드는 관리가 시급한 항목을 우선적으로 표시한다.

**표시 우선순위**

1. 관리 지연
2. 오늘 관리
3. 관리 임박
4. 관리 예정

미설정 항목은 별도 안내 영역에서 확인할 수 있도록 한다.

**처리 규칙**

- 같은 상태의 항목은 예정일이 빠른 순서로 정렬한다.
- 관리 대상 선택 시 해당 상세 화면으로 이동한다.
- 관리 기록을 저장하면 홈의 상태를 갱신한다.
- 관리 주기 또는 최근 관리일이 없는 항목에는 설정을 유도하는 안내를 제공한다.

**완료 기준**

- [ ] 관리 시급도에 따라 항목이 정렬된다.
- [ ] 관리 항목 상세 화면으로 이동할 수 있다.
- [ ] 데이터 변경 시 홈 화면이 갱신된다.

## 4. F03. 관리 히스토리

### F03-01. 관리 완료 기록 등록

**설명**

사용자는 실제 관리 작업을 완료한 후 관리 기록을 등록할 수 있다.

**입력값**

| 항목              | 필수 여부 | 설명                |
| ----------------- | --------- | ------------------- |
| 관리 대상         | 자동 지정 | 연결된 관리 대상    |
| 관리 날짜         | 필수      | 오늘 또는 과거 날짜 |
| 사용 제품 및 부품 | 선택      | 텍스트              |
| 관리 메모         | 선택      | 텍스트              |
| 기록 유형         | 자동 지정 | 관리 완료           |

**처리 규칙**

1. 관리 날짜를 필수로 입력받는다.
2. 미래 날짜는 등록할 수 없다.
3. 동일한 관리 대상에 같은 날짜의 기록을 여러 개 등록할 수 있다.
4. 저장 버튼의 반복 클릭으로 동일 요청이 중복 처리되지 않도록 방지한다.
5. 저장에 성공하면 해당 기록을 히스토리에 추가한다.
6. 최근 관리일과 다음 관리 예정일을 재계산한다.
7. 홈 대시보드의 관리 상태를 갱신한다.

**완료 기준**

- [ ] 오늘 날짜의 기록을 등록할 수 있다.
- [ ] 과거 날짜의 기록을 등록할 수 있다.
- [ ] 미래 날짜 등록을 제한한다.
- [ ] 동일 날짜의 여러 기록을 허용한다.
- [ ] 중복 제출을 방지한다.
- [ ] 저장 후 관리 일정이 갱신된다.

### F03-02. 초기 설정 기록

**설명**

온보딩에서 사용자가 입력한 최근 관리일을 히스토리에 저장한다.

**처리 규칙**

1. 최근 관리일이 입력된 경우에만 초기 설정 기록을 생성한다.
2. 기록 유형은 '초기 설정'으로 구분한다.
3. 실제 관리 날짜는 사용자가 입력한 날짜를 사용한다.
4. 사용 제품과 메모는 입력되지 않아도 된다.
5. 초기 설정 기록도 최근 관리일 계산에 포함한다.
6. 초기 설정 기록은 히스토리에서 구분하여 표시한다.

**완료 기준**

- [ ] 온보딩 날짜가 초기 설정 기록으로 저장된다.
- [ ] 초기 설정 기록을 일반 관리 완료 기록과 구분할 수 있다.
- [ ] 초기 설정 기록이 예정일 계산에 반영된다.

### F03-03. 항목별 히스토리 조회

**설명**

관리 항목 상세 화면에서 해당 항목의 관리 기록만 조회한다.

**처리 규칙**

1. 선택한 관리 대상의 기록만 표시한다.
2. 실제 관리 날짜 기준 최신순으로 정렬한다.
3. 기록 유형과 관리 날짜를 표시한다.
4. 사용자가 기록을 선택하면 상세 내용을 확인할 수 있다.
5. 기록이 없으면 빈 상태 안내를 표시한다.

**완료 기준**

- [ ] 해당 항목의 기록만 조회된다.
- [ ] 실제 관리 날짜 기준 최신순으로 표시된다.
- [ ] 기록 상세 내용을 확인할 수 있다.

### F03-04. 전체 히스토리 조회

**설명**

사용자는 하단 히스토리 탭에서 모든 관리 대상의 기록을 조회할 수 있다.

**처리 규칙**

1. 등록된 모든 관리 대상의 기록을 조회한다.
2. 실제 관리 날짜 기준 최신순으로 정렬한다.
3. 관리 대상 이름과 공간 및 관리 날짜를 표시한다.
4. 기록 선택 시 해당 기록의 상세 내용을 확인할 수 있다.
5. 기록이 없으면 빈 상태 안내를 표시한다.

**완료 기준**

- [ ] 전체 관리 기록을 조회할 수 있다.
- [ ] 관리 대상과 공간을 구분할 수 있다.
- [ ] 날짜 기준 최신순으로 정렬된다.

### F03-05. 관리 기록 수정

**설명**

사용자는 기존 관리 기록의 날짜와 내용을 수정할 수 있다.

**수정 가능 정보**

- 관리 날짜
- 사용 제품 및 부품
- 관리 메모

**처리 규칙**

1. 수정한 관리 날짜는 오늘 또는 과거여야 한다.
2. 수정 내용을 저장하면 기존 기록을 갱신한다.
3. 메모 또는 사용 제품만 변경된 경우 관리 일정은 유지된다.
4. 관리 날짜가 변경된 경우 최근 관리일을 다시 계산한다.
5. 최근 관리일 변경에 따라 다음 관리 예정일과 상태를 갱신한다.
6. 초기 설정 기록의 날짜도 수정할 수 있다.

**완료 기준**

- [ ] 기록 내용을 수정할 수 있다.
- [ ] 미래 날짜로 수정할 수 없다.
- [ ] 관리 날짜 변경 시 예정일이 재계산된다.
- [ ] 다른 기록은 변경되지 않는다.

### F03-06. 관리 기록 삭제

**설명**

사용자는 기존 관리 기록을 삭제할 수 있다.

**처리 규칙**

1. 삭제 전 확인을 요청한다.
2. 사용자가 취소하면 기록을 유지한다.
3. 확인하면 해당 기록만 삭제한다.
4. 남은 기록을 기준으로 최근 관리일을 다시 계산한다.
5. 최근 관리일 변경에 따라 다음 관리 예정일과 상태를 갱신한다.
6. 모든 기록이 삭제되면 최근 관리일과 예정일을 미설정으로 처리한다.

**완료 기준**

- [ ] 기록 삭제 전 확인을 요청한다.
- [ ] 선택한 기록만 삭제된다.
- [ ] 가장 최근 기록 삭제 시 일정이 재계산된다.
- [ ] 모든 기록 삭제 시 미설정 상태가 된다.

## 5. 공통 기능

### C01. 온보딩 진행 상태 자동 저장

**처리 규칙**

- 온보딩의 현재 단계와 입력 내용을 자동 저장한다.
- 온보딩 완료 전 이탈한 경우 진행 상태를 유지한다.
- 재방문 시 저장된 정보를 복원한다.
- 온보딩 완료 후에는 일반 서비스 화면으로 진입한다.

**완료 기준**

- [ ] 온보딩 중 페이지를 종료해도 입력 내용이 유지된다.
- [ ] 재방문 시 진행 상태를 복원한다.
- [ ] 완료한 사용자는 온보딩을 반복하지 않는다.

### C02. 하단 탭 내비게이션

**탭 구성**

- 홈
- 관리 대상
- 히스토리

**처리 규칙**

- 각 탭을 선택하면 해당 화면으로 이동한다.
- 관리 항목 상세와 관리 완료 기록은 하위 화면으로 제공한다.
- 하위 화면에서 이전 화면으로 돌아갈 수 있다.

**완료 기준**

- [ ] 세 탭 사이를 이동할 수 있다.
- [ ] 관리 항목 상세 화면에 진입할 수 있다.
- [ ] 하위 화면에서 이전 화면으로 돌아갈 수 있다.

### C03. 저장 및 오류 처리

**처리 규칙**

- 필수 입력값을 검증한다.
- 저장 중에는 중복 제출을 방지한다.
- 저장 성공 시 결과를 사용자에게 안내한다.
- 저장 실패 시 오류를 안내한다.
- 저장 실패 시 기존 입력 내용을 가능한 한 유지한다.
- 삭제 작업은 사용자 확인 후 수행한다.

**완료 기준**

- [ ] 잘못된 입력을 안내한다.
- [ ] 중복 제출을 방지한다.
- [ ] 저장 성공과 실패를 구분하여 표시한다.
- [ ] 삭제 취소 시 데이터가 유지된다.
