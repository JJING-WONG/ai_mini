# 관리 대상 기능 확인 (4단계)

## 실제 사용자 흐름

온보딩 완료 후 `/items/new`에서 기본 공간·등록 공간을 고르거나 '직접 공간 추가'로 새 공간을 선택합니다. 새 공간은 항목 저장 시 함께 등록되며 취소하면 등록되지 않습니다.
기본 항목을 선택하면 이름과 recommendedIntervalDays를 초기 입력값으로 복사합니다. 직접 입력은 templateId가 null입니다.
이름·공간은 필수이고, 주기는 양의 정수 또는 미설정입니다. 모델명·규격·메모·이미지는 선택입니다.
저장 성공 후 상세 화면으로 이동하며 실패하면 입력값과 이미지·임시 공간을 현재 화면에 유지합니다. 저장하지 않은 일반 항목 폼은 새로고침 시 복원하지 않습니다.

`/items/:itemId/edit`는 기존 값과 이미지를 표시합니다. 저장 후 ID·생성일과 관리 기록은 유지합니다.
기본 항목은 이름·소속 공간을 바꿔도 templateId를 유지합니다. '직접 등록 항목으로 전환'을 명시적으로 선택하고 저장하면 null로 해제합니다. 저장 전에는 기존 연결로 되돌릴 수 있습니다.
항목 삭제는 상세 화면 확인창에서 실행합니다. 해당 항목과 연결된 기록만 함께 삭제하고 목록으로 이동합니다. 공간과 다른 항목·기록은 유지합니다.
5단계에서 주기 수정 후 다음 관리일·상태 재계산을 연결했습니다.

## 이미지

PNG·JPEG·WebP·GIF, 1MB 이하 파일을 지원합니다. 파일을 읽고 이미지로 표시 가능한지 확인한 뒤 data URL로 항목에 저장합니다.
수정 시 기존 이미지를 유지·교체·제거할 수 있습니다. 확인 중에는 저장을 막고, 형식·용량·읽기 오류를 안내합니다.
브라우저 저장 용량이 부족하면 저장 실패로 처리하고 이전 원본을 복구합니다.

## 개발용 디자인 미리보기

- `/items/new?preview=template`
- `/items/new?preview=filled`
- `/items/new?preview=errors`
- `/items/new?preview=save-error`
- `/items/preview-ac/edit`

명시적인 디자인 미리보기에서는 실제 데이터를 저장·삭제하지 않습니다.

## 저장 및 검증

Context의 addItem/updateItem/deleteItem → Service → Repository 순서로 처리합니다.
공간·항목·기록 변경은 공통 복구 키 `homeguide:pending-data`를 사용해 일괄 저장하고, 실패·중단 시 이전 원본을 복구합니다.
자동 테스트와 서버 렌더링으로 저장 후 재조회, 템플릿 연결 정책, 이미지 값 유지, 연관 기록 삭제 및 실패 복구를 확인했습니다.
실제 브라우저의 파일 선택·클릭·새로고침·모바일 배치는 연결 오류로 검증하지 못했습니다.
